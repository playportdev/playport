## Why

There are three NT sync paths today, and one of them is broken:

| Path | State | Problem |
| --- | --- | --- |
| Server waits | always | every wait and wake is a round trip to the in-process wineserver (45–150 µs) |
| fastsync (`MADEIRA_FASTSYNC=auto`, wine-unix 0015–0017, madeira-unix 0081) | on (0054) | events, plus semaphores on request; only single-object, non-alertable waits; about 2,200 lines of its own protocol over five server files |
| madsync (`inproc-sync = 1`) | off (0014, 0023) | system APCs never run in its waits (named-pipe reads return 0 bytes; RDR2's launcher, 0142); one global mutex |

Wine's upstream in-process code (`inproc_sync`) covers every waitable object and every kind of
wait. What it lacks on iOS is a driver that the server can use to interrupt a waiter.

## Design

`build/ppsync/README.md`. In short:

- A library implementing the ntsync driver's interface, owned by Playport (`build/ppsync`). It
  is copied into the Madeira tree by `build/stages/unix.sh` and compiled in place of
  `build/madsync`.
- Per-object locks. A global lock is taken only for wait-all.
- Waker-satisfies-waiter with a CAS. Each thread has a futex word.
- The server reaches a waiting thread with `ppsync_kick`, for a system APC or the thread's end
  (`ECANCELED`, after which ntdll makes a zero-timeout server wait), and with `ppsync_freeze`
  for logical suspension (it is neither satisfied nor released while suspended, as a server
  wait is).
- Lock-free only for single-object polls that find the object not ready.

## Chunks

1. **Engine and host tests**: `build/ppsync/*`, and `pp test` runs `ppsync_test.c` plainly
   and under TSan. Check: `pp test --quick`.
2. **Wine side** (`patches/wine-unix`):
   - drop fastsync (0015, 0016, 0017) and rebase the later patches;
   - a new patch that renames madsync's calls to ppsync's;
   - `linux_wait_objs` handles `ECANCELED`;
   - the server kicks on a system APC and on `kill_thread`, and freezes and thaws on
     suspend/resume (`thread.c`, `process.c`).
3. **Madeira side** (`patches/madeira-unix`):
   - drop 0014 (madsync opt-in) and 0081 (fastsync flush);
   - a new patch building `build/ppsync` in place of `build/madsync` in
     `build/ntdll-unix/build.sh` and `build/wineserver/build.sh`;
   - `server_ios.c` uses `PPSYNC_DEVICE_FD`;
   - `unix.sh` copies `build/ppsync` in, and `build/pipeline` puts it in the unix digest.
4. **App**:
   - the Settings › Developer switch becomes "In-process sync" (`PLAYPORT_PPSYNC=0`) in
     place of fastsync's `MADEIRA_FASTSYNC`;
   - every game's `env.MADEIRA_FASTSYNC_SEM=1` default (`LaunchSettings.everyGame`, decision 0153) goes, since it has no effect any more;
   - docs (ARCHITECTURE.md, UPSTREAM-SYNC.md);
   - decision record 0157 (proposed).
5. **Build in the side copy**: `pp build` and `pp verify`. Commit the path-independent
   record rows.
6. **Phone (main checkout, after the move)**:
   - Hollow Knight first frame+10;
   - a named-pipe check (`proc.named_pipe_*` ladder rung);
   - RDR2's launcher reaching its service with ppsync on;
   - `pp perf` against fastsync on Hollow Knight and on The Witcher 3 or RDR2.

   Then 0157 is accepted, or the branch is reverted.
