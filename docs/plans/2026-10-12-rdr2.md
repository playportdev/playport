## What Madeira's run proves, and what it does not

Madeira took RDR2 from a crash in `DllMain` to Story mode on the phone between 2026-09-16 and
2026-09-24 [M §1–§132]:

- the menu, the benchmark and story cutscenes;
- free play at 20–48 fps, depending on the scene and the power clamp;
- about 9 minutes of story before a crash (§80), and 23 minutes of riding in a later run (§114).

That work is the strongest evidence we have that the game can run in one iOS process at all.
**It is not evidence for Playport's path:**

| | Madeira's RDR2 run [M §67.1] | Playport's path |
| --- | --- | --- |
| Copy | DRM-modified: a third-party bypass DLL (`EMP.dll`) replaces Social Club and the launcher check, rewrites the main image at run time and runs a bytecode VM [M §67.1, §21] | a genuine copy only (decision 0004's residual-risk rule: only owned titles and genuine clients run) |
| Launcher | none: the bypass faked it, and `Launcher.exe` was the bypass's | the genuine Rockstar Games Launcher and Social Club, both Chromium Embedded Framework (CEF) apps (see [the launcher chain](#2-the-launcher-and-drm-chain)) |
| Direct3D 12 | `madeira_d3d12.dll`, Madeira's own D3D12-on-Metal runtime, with Apple's IR converter for DXIL and DXMT's airconv for SM5.1 | not shipped and not built (docs/LICENSING.md; decision 0007). Vulkan is the direction (decision 0100) |
| Memory | an opt-in file-backed guest data tier (`ml1077`, `MADEIRA_SWAP_FILE`) moved about 2.2 GB of guest heap off the footprint [M §77, §80] | the code is in the pinned ntdll, but Playport's host never arms it: no `MADEIRA_SWAP_FILE` in `app/Sources`. - the fixed-base executable window at `0x140000000` [P ARCHITECTURE.md, "JIT pool placement"];

## 1. RDR2's demands

### Vulkan or DX12

RDR2 ships both renderers: Vulkan 1.1, with its own `vulkan-1.dll` loader (1.1.108), and
Direct3D 12 [W PCGW]. PCGW notes that DX12 "may incur a performance penalty compared to Vulkan,
depending on the GPU". **Decided (D6, 2026-10-13): Vulkan**, with vkd3d-proton as the
fallback. The reasons:

- **One translation layer fewer.** RDR2's Vulkan calls go through winevulkan straight to
  KosmicKrisp: SPIR-V is translated to MSL and nothing else sits in between. DX12 would add
  vkd3d-proton's DXBC/DXIL-to-SPIR-V translation, descriptor emulation and command recording on
  the game's render thread.
- **What that layer costs, measured.** On Hollow Knight, vkd3d's UnityGfxDeviceWorker does about
  twice DXMT's work per frame (20.1 against 9.5 Mi/f), and the whole frame costs +22 % to +31 %
  Mi/f against DXMT [P 2026-10-06-vulkan-perf-baseline, 2026-10-08-vulkan-perf-standing].
  RDR2 is CPU-bound on one critical thread in its slow scenes [M §67.3, §106], so this is the
  overhead that hurts most here.
- **Policy.** Decision 0100 (Vulkan is the direction) does not choose between these two
  routes; both are Vulkan routes. Decision 0044 routes a game to vkd3d only when its executable
  imports `d3d12.dll`, which RDR2's does (inference). So RDR2 needs an **explicit per-game
  Vulkan choice and RDR2's own API setting**:
  - RDR2's setting is `<API>kSettingAPI_Vulkan</API>` in its `system.xml` [W PCGW].
  - The per-game choice already exists in Game options.
  - What does not exist yet is a way to write the game's settings file without a side
    entrance. Decision 0012 forbids pushing files from the workstation, so the player must set
    the API in the game's own menu.
- **The cost of choosing Vulkan.**
  - **No native Vulkan PE title has been shown on the phone yet.** The route exists
    (decision 0015 lists "Vulkan titles natively"), but every Vulkan run so far went through
    DXVK, vkd3d or Zink.
  - **RDR2's own loader may find no driver.** RDR2 loads the `vulkan-1.dll` it ships.
    Proton's Wine forces native `vulkan-1` for RDR2 (Valve commit `2c09b684a4d`,
    "wine.inf.in: Use native vulkan-1 for RDR2", marked `inert` for Playport in
    `docs/evidence/2026-09-28-wine-proton-rebase/valve-commits.tsv`). A native Khronos loader
    finds winevulkan through the `HKLM\Software\Khronos\Vulkan\Drivers` registry key, and
    `app/registry/system.reg` has no Khronos key. Madeira's loader also never swaps a builtin in
    for a DLL already mapped from the game's directory [P 2026-09-26-witcher3-profile §0]. So
    the game's loader probably finds no ICD (inference; host-checkable). This is prerequisite
    P3.
  - **Feature coverage is unknown.** RDR2's Vulkan renderer has not run on KosmicKrisp.
    KosmicKrisp is Mesa's Vulkan 1.4 driver on Metal 4 (decision 0014) and has geometry and
    tessellation through Mesa's `poly` library [P 2026-09-26-kosmickrisp-gs-fill-host]. RDR2
    uses tessellation for snow and ground: Madeira's runtime dropped 27 pipelines and about
    28k draws per run until it implemented tessellation [M §67.5 item 8, §81–§82].
    **Measured 2026-10-17 (PLA-386):** under desktop Proton with RADV masked to
    KosmicKrisp's profile the renderer (Vulkan 1.1, engine SGA) reached its landing page; it
    uses no feature KosmicKrisp lacks, but hits three KosmicKrisp defects (a texture lowering
    abort in 153 pipelines, pipeline-statistics query pools, 8-sample pipelines) and shows a
    video-memory warning on a unified-memory device. Fixes are chunks V0–V3 of the
    [FL12_2 plan](2026-10-05-kosmickrisp-fl12_2.md#rdr2-on-vulkan-chunks-v0v3)
    ([evidence](../evidence/2026-10-17-rdr2-vulkan-needs.md)).
- **The fallback is DX12 through vkd3d-proton.** That route already reaches feature level
  12_0 on KosmicKrisp (decision 0032), but it froze once in the Hollow Knight standing runs
  [P 2026-10-08-vulkan-perf-standing].

### CPU features

- **AVX is not needed.** FEX on iOS reports no AVX (`patches/fex-port` 0009; decision 0018).
  Madeira ran RDR2 with "AVX off (SSE paths)" [M §67.5 item 3], so the game has a path without
  AVX. The minimum CPUs (i5-2500K, FX-6300) have AVX [W PCGW], but the game does not require it.
- **SSE4.2 and POPCNT:** FEX provides them (it reports SSE up to 4.2). Madeira's run is the
  proof that the game's SSE paths run under FEX.
- **AFP.** FEX on iOS hard-codes AFP, and switching FPCR cost 8.3 % of the Witcher 3 profile.
  `patches/fex` 0005 lets `FEX_HOSTFEATURES=disableafp` turn it off, but AFP stays on by
  default because MXCSR.DAZ needs it [P 2026-09-26-witcher3-profile §4]. This was first found
  in RDR2 [M §111–§112]. It is a per-title lever, not a blocker.
- **TSO.** RDR2.exe has no volatile metadata, so every load and store pays for TSO ordering.
  Turning TSO off globally livelocked the load [M §64, §122]. Selective TSO is a later lever
  (decision 0021 covers per-game ordering).

### Memory and address space

- **Requirements.** Minimum 8 GB RAM and 2–3 GB VRAM; recommended 12 GB and 4–6 GB [W PCGW].
- **The phone's limit.** Playport's phone (iPhone18,4, A19 Pro, 12 GB) gives the app 8,192 MB
  with the increased-memory-limit entitlement and Game Mode, and 6,144 MB before Game Mode
  raises it [P 2026-09-28-memory-limit]. Every Play spends 512 MiB of that on the JIT pool
  (decision 0036).
- **What Madeira measured on the same 8,192 MiB limit**, with the bypass in place of the
  launcher:

  | State | Footprint | Notes |
  | --- | --- | --- |
  | Benchmark and cutscenes, no file-backed tier | killed at 8,184–8,192 MB [M §52, §73–§75] | guest heap 4.4–4.6 GB; GPU (tag 100) 2.3–2.6 GB, of which about 1.4 GB is resource payload; JIT pool about 490–592 MB; FEX about 300–335 MB; native malloc 600–670 MB |
  | Story, file-backed tier on (3,072 MB cap) | plateau at 7.2–7.4 GB, 2.2 GB file-backed [M §80] | about 9 minutes of play, then a crash (a GPU hang, then a NULL read) |
  | Story, a later run | plateau at 8,100–8,185 MB, then killed [M §113] | the tier had 750 MB to spare; its eligibility rule (single commits of 8 MB or more), not its cap, was the limit |
  | Game Mode dropping the limit | killed [M §117] | the limit fell, a separate cause of kills |

  - **The game's controls do not shrink it.** Its texture budget follows the advertised VRAM
    (1,024 MB is refused by the game itself; 1,280–2,304 MB is accepted), and it polls the
    budget 930k times a run without trimming [M §75–§76]. The same was true of Kingdom Come
    under Playport [P 2026-10-01-kcd-memory].
- **Address space.**
  - The game reserves max(7/8 × reported physical memory, 8,960 MB) in one piece
    [M §33–§34]. Madeira's `jumbo` path serves this in the `[0x74, 0x7c)` band; the Witcher 3
    used 32 GB of that band the same way [P 2026-09-26-witcher3-profile §2].
  - The STEAM_CEF_HANDOFF VA map gives the same `[0x74, 0x7c)` to CEF's four 16 GB
    PartitionAlloc pools [M STEAM_CEF_HANDOFF §1].
  - **A CEF launcher process alive beside RDR2 competes for that band.** Whether both fit in
    the about 64 GB of usable VA is **not determined**, and it is the first thing to measure
    (stage S2).
- **Verdict on memory (inference):**
  - With a genuine copy, the launcher and Social Club stay alive beside the game (see §2).
    Their CEF processes add memory Madeira never paid: on the order of 0.5–1.5 GB, an estimate
    to be measured in S2. Madeira's Steam client with CEF peaked at 3.0–3.4 GB, but that is the
    whole Steam client, not one launcher.
  - Playport's Vulkan path cost about 700 MiB more than DXMT on Hollow Knight
    [P 2026-10-06-vulkan-perf-baseline].
  - **Inside the app's own 8 GB, Story mode does not fit on this phone.**
  - **Memory is a dependency on PLA-216, not a wall.** The budget below sets out what PLA-216
    must deliver.

### RDR2's memory budget against donor memory (PLA-216)

**What PLA-216 has shown [E]:**

- **4 GiB moved off the app.** Memory that the JIT helper creates (a ledger-tagged named
  memory entry), sends over XPC and the app maps, is charged to the **helper's** footprint, not
  the app's. 4 GiB of incompressible data was verified in both processes on this phone. The
  helper's own limit was 6 GiB.
- **No hidden footprint.** Asking for `VM_LEDGER_FLAG_NO_FOOTPRINT` is refused
  (`KERN_NO_ACCESS`).
- **Real game allocations ran on it.** Hollow Knight launched and played with FEX's data band
  backed this way (madeira-unix hook 0126), with 0 fallbacks. Only about 30 MiB left the app's
  footprint.
- **Kingdom Come showed no peak gain.** With FEX-only backing its peak was 7,468 MiB off against
  7,554 MiB on, one pair; about 75 MiB was charged to the helper.

**Why the Kingdom Come result matters for RDR2.** It does not refute the approach, but it shows
where the approach must reach:

- **Backing the wrong part moves nothing.** FEX's data band is about 0.3 GB of an
  8 GB footprint, and run-to-run streaming variance in a large game is bigger than that.
  RDR2's footprint is guest heap (3.9–4.6 GB) and GPU memory (2.3–3.1 GB) [M §67.3, §113]. The
  hook that matters is the guest-commit hook 0127 (fresh RW commits of at least 1 MiB in
  `[0x7000000000, 0x7c00000000)`). **0127 has never run on the phone** and is capped at 2 GiB.
- **The game's own budgets must be held fixed.** Kingdom Come was told 8,192 MiB of RAM and
  1,536 MiB of VRAM in both runs, and an earlier run showed that telling it less does not shrink
  it [P 2026-10-01-kcd-memory]. RDR2 sizes its reservation and texture pool from what it is
  told [M §33, §75]. Memory freed by PLA-216 is only margin if the game is not told it has more
  (P7).
- **The ceiling is unproven.** The measured design is the app's limit plus one *living*
  helper's, at most 8 + 6 GiB, and jetsam may end the helper under pressure. The donor variant
  (H1: the pages stay mapped, charged to nobody, after the donor dies) is PLA-216's step 1 and is
  **untested**.

**The budget.** Rows are Madeira's measurements with no launcher [M §67.3, §75, §113], plus
Playport's additions (inference):

| Part | Size | Can PLA-216 move it off the app? |
| --- | --- | --- |
| Guest heap (the game's arenas and streaming) | 3.9–4.6 GB | **yes**, through 0127 (PLA-216 step 3), once its 2 GiB bound is raised to the pool size |
| Launcher and Social Club (CEF heaps, in the guest band) | 0.5–1.5 GB (estimate) | **yes**, the same hook, if their commits qualify (1 MiB or more, plain RW). CEF's PartitionAlloc pools do lie in `[0x74, 0x7c)` |
| GPU memory (Metal, tag 100): textures, buffers, driver metadata | 2.3–3.1 GB | **no** today. PLA-216 step 5 (stretch) covers buffers only, through `VK_EXT_external_memory_host` on KosmicKrisp; textures stay with the app |
| Vulkan route's extra over a direct Metal runtime | about 0.7 GB (Hollow Knight's figure) | no (driver and GPU side) |
| JIT pool | 512 MiB | no (excluded from PLA-216 by design) |
| FEX host band | about 0.3 GB | barely: hook 0126 moved 30–90 MiB |
| Native malloc, Wine and the Metal driver | 0.6–0.7 GB | no |

What that adds up to (inference):

- **Base limit only (8,192 MiB, Game Mode on).** Everything above comes to roughly 9–11.5 GB,
  so 1–3.5 GB too much. Story mode is killed, as Madeira's was even without the launcher.
- **With donor memory backing the guest heap.**
  - The app keeps only what PLA-216 cannot move: GPU, pool, FEX, malloc and the Vulkan extra,
    about 4.4–5.3 GB. That leaves 2.9–3.8 GB of the app's 8 GB for whatever guest heap is not
    backed (sub-1 MiB commits, ranges copied back on a protection change).
  - Donors carry about 4–6 GB. That is within one helper's measured 6 GiB, or several donors if
    H1 holds.
  - **On the app's ledger, Story mode fits.**
- **What is still missing:**
  1. **0127 on the phone at all,** with its bound raised from 2 GiB to about 6 GiB, and its
     copy-back rate measured on a protected title (PLA-216 step 3 names the PLA-203 family).
  2. **A ceiling above one living helper,** or proof that one helper's 6 GiB survives a
     30-minute session (PLA-216 steps 1–2).
  3. **Physical RAM.** The phone has 11.7 GiB. App-resident 4.4–5.3 GB plus donor-resident
     4–6 GB is 8.4–11.3 GB, before iOS itself. Compression and the game's touched-but-idle
     pages decide whether that fits; system-wide jetsam still applies. This is the honest outer
     limit, and only a run shows it.
  4. **GPU memory** stays on the app. If RDR2's Vulkan GPU footprint is at the top of the range
     (3.1 GB plus the 0.7 GB Vulkan extra), the app keeps about 5.3 GB of unmovable memory.
     PLA-216 step 5 is then needed too.
  5. **The release build.** PLA-216 is dev-only. Shipping it needs a decision record with the
     owner's sign-off, and an iOS update could close the technique.
- **The fallback is the file-backed tier** (Madeira's `ml1077`, P4). It held 2.2 GB off the
  footprint in Story mode [M §80], at the cost of flash writes and possible hitches. It is
  complementary to PLA-216 rather than a rival: it backs to flash, PLA-216 to another process's
  RAM. Use it if PLA-216's step 1 or 3 fails.

### Install size and storage

- **Size.** PCGW's minimum is 150 GB [W PCGW]; Madeira's container held a 117 GB install
  [M §51.1]. On top of that come the launcher (about 1 GB, inference), the shader caches and a
  file-backed tier file (up to 3 GB).
- **Free space.** The phone had 137.8 GB free on 2026-09-24 and 42.95 GB on 2026-09-25, after
  The Witcher 3 [P 2026-09-24-p2-install-engine, 2026-09-25-witcher3-setup]. Its capacity and
  today's free space are not recorded. **Installing RDR2 probably means removing other large
  titles first** (owner decision D5, decided: the largest installed titles not in active work,
  chosen at S3).
- **Install route.**
  - A Steam copy downloads through Playport's native Steam installer, which has been shown at
    104 GB (The Witcher 3).
  - An Epic copy downloads through Playport's Epic import (decision 0059 and the PC-import
    plan).
  - A copy bought from Rockstar can only be downloaded by the launcher itself, inside the
    guest. That would be about 120 GB through Wine's network stack, and it is untested. D1
    avoids it.

### Shader compilation

- **What RDR2 does.** Its Vulkan renderer builds its pipelines while loading and keeps its own
  pipeline cache. Changing the API forces the cache to rebuild; PCGW documents the error this
  gives and the `system.xml` fix [W PCGW].
- **What the phone does with that.** Every pipeline goes SPIR-V → NIR → MSL → Metal compile on
  the phone. Madeira saw "cold-cache double compile" and pipelines dropped until tessellation
  existed [M §81].
- **The cache size.** Mesa's disk cache, one for every title, is capped at 1 GB since
  PLA-279 (it was 256 MB; [evidence](../evidence/2026-10-14-shader-caches.md)). Measure RDR2's
  pipeline set against it before a per-title size (N7).
- **Expect a first load of many minutes.** Madeira's loading took about 5 minutes on its own
  runtime [M §67.2]. It is also the phase that spends the burst energy budget (see Thermals).

### Expected performance (reasoned estimate)

What was measured:

- **Madeira on an A20 Pro**, own D3D12-on-Metal runtime, bypass in the frame [M §67.2, §101,
  §114, §131–§132]:
  - 960x540 Low: benchmark average 21–22 fps;
  - after the CPU work: benchmark 32.6 fps;
  - 1408x648 at 3/4 resolution scale: 60 fps for 47–85 s after loading, then 40–48 fps standing
    and 23–33 fps riding in Story mode once the power clamp sets in.
- **The Witcher 3 under Playport on this phone** (A19 Pro, iPhone Air), Low, 1954x900: 25–30 fps
  from a cool start, GPU-bound at about 35 ms a frame. With the P cores parked at the 660 mW
  budget floor it fell to 15 fps [P 2026-09-26-witcher3-profile].
- **The Vulkan route's overhead** on Hollow Knight: DXVK costs +14–18 % CPU work per frame over
  DXMT, vkd3d +22–31 %, and GPU time at native resolution is within 4–29 %
  [P 2026-10-06-vulkan-perf-baseline, 2026-10-08-vulkan-perf-standing].

Estimate for Story mode on this phone, through RDR2's Vulkan renderer on KosmicKrisp, at about
720 rows, Low, at 3/4 scale or below (inference):

- **About 15–25 fps sustained, with bursts of 30–40 fps** for the first minute after a load.
- **Why lower than Madeira's.** The A19 Pro is a generation older than Madeira's A20 Pro, and
  the Air sustains less power: the Witcher 3 shows it reaching the 660 mW floor. KosmicKrisp's
  CPU cost per draw is above a direct Metal runtime's: Madeira's submission worker alone was
  about 21 % of instructions per frame [M §119]. The genuine executable's own protection adds
  unknown work.
- **Why not lower still.** The bypass's VM and self-modifying writes are gone. RDR2's Vulkan
  path skips vkd3d.
- **30 fps sustained is not a realistic target on this phone**; 20 fps is.

### Thermals

- **The clamp.** Madeira found that the SoC clamps CPU clocks once a one-time energy allowance
  is spent: about 425 J of CPU energy from launch, and the GPU's energy counts too. fps then
  halves at unchanged work per frame [M §119, §128, §131]. Game Mode off changed nothing, and
  there is no entitlement or bypass [M §120–§121].
- **Levers Madeira found:**
  - running loading in a low-energy mode doubled the time at 60 fps (38 s to 85 s) [M §128];
  - 3/4 resolution scale gave +20–25 % fps after the clamp [M §131].
- **On the Air.** Playport's runs on this phone already show the floor that parks the P cores,
  and that charging adds heat [P 2026-09-26-witcher3-profile §1, 2026-09-25-hk-thermal-baseline].
- **What to expect (inference):** RDR2 sessions will run "serious" within minutes, and every
  measurement must report thermal state and the budget (`pp perf --cool`).

## 2. The launcher and DRM chain

### What is mandatory

- **Every copy needs the Rockstar Games Launcher.** PCGW: "All versions require Rockstar Games
  Launcher" as DRM, whichever store sold them (Steam 1174180, Epic, Rockstar's own store and
  resellers) [W PCGW]. A Steam or Epic copy also needs that store's ownership check, passed
  through the launcher.
- **The process chain.** `RDR2.exe` starts, loads its modules, starts the launcher and exits.
  The launcher then starts `RDR2.exe` again, which does the real work. Madeira saw this chain,
  with the bypass's own launcher [M §1, §36–§37].
- **The executable window must be re-granted.** Both RDR2 generations need the fixed base
  `0x140000000`, because the executable has no `.reloc` and clears DYNAMIC_BASE. `ml983`
  re-grants the window when the first generation is reclaimed; if the first generation's
  image is left mapped, the second runs the dead one's code [M `virtual_ios.c` comment at
  `ml983`]. Playport's madeira-unix 0089 builds on this.
- **The launcher and Social Club stay alive while the game runs (inference).** The game's
  `ERR_NO_LAUNCHER` check [M §37] and the in-game Social Club overlay on the Home key [W PCGW]
  both point that way. Their CEF processes live in the game's one Mach task, so a crash in any
  of them kills the game (STEAM_CEF_HANDOFF §1).
- **The installers.** The launcher's own installer and its Social Club installer need msiexec
  (staged since decision 0103) and possibly a Windows service. Whether the runtime starts a
  Windows service is not determined; the launchers plan owns this.

### Online and offline

- **Offline mode exists, but needs a signed-in first run.** The launcher has an offline mode,
  but first needs an online sign-in with "Remember my password" and auto sign-in, and each game
  must be run once online. Even when bought on Steam, the game must then be started from the
  launcher [W PCGW RGL].
- **`-scofflineonly`** turns off Social Club's online features in the game [W PCGW]. It is the
  default for Story-mode testing here: a smaller network surface, and nothing for Online.

### Story mode against Red Dead Online

- **Anti-cheat.** PCGW lists no anti-cheat for RDR2. GTA V added BattlEye on 2024-09-17, and
  GTA V Enhanced uses BattlEye [W PCGW]. Whether Red Dead Online has, or will get, the same is
  **not determined**. Rockstar enforces Online rules server-side regardless.
- **The account-ban risk.**
  - RDR2 is licensed to the Rockstar account.
  - A Steam copy links to one Rockstar account for good (inference from Rockstar's account
    linking).
  - A modified or unusual client in Online can get the Rockstar account banned. That ban
    would take every Rockstar title on the account with it (inference).
  - Story mode under Proton is routine. Online under Proton works for many players
    (ProtonDB Gold trending Platinum, 1,463 reports [W ProtonDB]). But under FEX on iOS the
    client is unusual: odd timing, odd CPUID and odd machine values (decision 0098).
- **Testing rule (proposed default; item 1 is D2 and D3, decided 2026-10-13):**
  1. Never start Red Dead Online on the owner's account. Online is out of scope for this plan.
  2. Story-mode runs use `-scofflineonly` once the first online activation is done.
  3. No workstation tool reads, injects into or alters the game's memory or files (the decision
     0012 rule already covers files).
  4. Any change to what the game fingerprints (decision 0098's machine values, the CPUID brand)
     is followed by one Story-mode check before anything else, as the anti-tamper replay rule
     does [P 2026-10-12-anti-tamper-replay].

### What Proton needs today

- **ProtonDB:** Gold, trending Platinum, 1,463 reports, confidence strong [W ProtonDB].
- **Proton's RDR2-specific changes in the pinned Valve commits:**
  - `2c09b684a4d`: native `vulkan-1` for RDR2. Inert here: the app never runs `wine.inf`.
  - `6932711b260`: "winex11.drv: HACK: Make sure popups are not managed for Rockstar
    Launcher". Unused here: winex11 is not in the iOS build.
  - Proton's CEF and launcher hacks for other launchers (Paradox's in-process GPU rendering,
    `ee9137915fa`, taken). These show that Proton treats CEF launchers one by one.
- **Not determined:** which other Proton components (DXVK-NVAPI, the launcher's service, font
  or locale fixes) RDR2 relies on. That needs Proton's source read for `Launcher.exe` and
  `RDR2.exe` matches, a host task for S0.

## 4. Prerequisites Playport needs first

**The memory prerequisite: [PLA-216](https://linear.app/playportdev/issue/PLA-216)** (donor and
helper-owned memory; done and merged, [outcome](finished.md#guest-ram-from-donor-processes)). Tier (c) depends on it; tier (b) benefits from
it. RDR2 needs these of its steps:

- **Step 1 (H1):** whether memory stays off every ledger after the donor dies. This decides
  whether the ceiling is one living helper's 6 GiB or more.
- **Step 2:** how much in total, and survival under system pressure.
- **Step 3:** the pool at Play feeding hook 0127, the guest heap. Its 2 GiB bound must be raised
  to about 6 GiB. Its copy-back on protection changes must be measured on a protected title.
- **Step 4:** Kingdom Come with the pool on, as the dress rehearsal. Its peak `fpMB` must fall
  by the backed amount with the game's RAM and VRAM budgets held fixed.
- **Step 5 (stretch):** GPU buffers through `VK_EXT_external_memory_host`. Needed only if RDR2's
  unmovable GPU share leaves too little room (see the budget).

RDR2 adds two requirements for PLA-216 to take into its plan (proposed as N1 below):

- a launcher's CEF processes beside a game;
- a 30-minute run with 4–6 GB backed.

## 6. Stages

Effort is in working sessions (about half a day each, one agent), for engineering only. Phone
time is extra. The stages run in order. S0–S2 do not need RDR2.

### S0: Host-only groundwork (no game, no phone)

- **Do:**
  - read Proton's source for RDR2 and Rockstar launcher matches;
  - add the Khronos ICD key to the registry seed and test the native-loader path with the
    host's `tools/tests` (P3);
  - write RDR2's memory budget into PLA-216 as a target (N1);
  - inventory which Madeira RDR2 changes are in Playport's pin and patches (`ml983`, `ml992`,
    `jumbo`, `ml1046`, `ml1077`; the window and sub-floor are already known).
- **Acceptance:** an evidence note listing each item as present, absent or armed; the ICD key
  host test passes; PLA-216 carries the RDR2 targets.
- **Phone gates:** none.
- **Effort:** 2–3 sessions.

### S1: A native Vulkan title, and PLA-216 on the phone (P2, P4)

- **Do:**
  - bring up a light native Vulkan x86-64 title;
  - PLA-216 runs its steps 1–4 under its own plan. This plan only adds RDR2's acceptance figure
    to its step 4.
  - If step 1 or 3 fails, arm the file-backed tier instead, behind a dev setting reached through
    the UI (decision 0012), off by default.
- **Acceptance:**
  - the Vulkan title reaches its first frame and runs 60 s;
  - Kingdom Come's peak app footprint falls by at least 2 GB with the guest heap backed, with
    its RAM and VRAM budgets unchanged and no p99 frame-time regression over 10 %
    (`pp perf --cool`);
  - a 30-minute session holds at least 4 GB backed with the data intact.
- **Phone gates:** Hollow Knight `first-frame+10` on DXMT and Vulkan; the title runs; Kingdom
  Come `pp perf` with backing off and on.
- **Effort:** 2–4 sessions here, plus PLA-216's own steps.

### S2: The Rockstar launcher on a stepping stone (P1, P5, P8; needs the launchers plan)

- **Do:**
  - Red Dead Redemption (or GTA IV) through the Rockstar launcher: install, first online
    sign-in, game start, offline mode;
  - measure the launcher's processes: footprint, VA bands, pool and FEX band use, all while the
    game runs.
- **Acceptance:**
  - the launcher signs in through Playport's UI;
  - the game reaches its menu;
  - `-scofflineonly` and offline mode work on a second run;
  - an evidence record gives the launcher's memory and VA cost beside the game.
- **Phone gates:** Hollow Knight `first-frame+10`; the stepping stone through `first-frame+60`
  with a shot; its Compatibility issue updated.
- **Effort:** 6–12 sessions beyond the launchers plan. The CEF work is the uncertainty.

### S3: RDR2 install and the launcher chain (tier a/b; D1 decided: the Steam copy; D5 at S3)

- **Do:**
  - install the Steam copy of the game (D1), once PLA-266 no longer refuses it;
  - run the first online activation by hand (the owner signs in);
  - set Vulkan in the game and in Game options;
  - play to the menu.
- **Acceptance:**
  - both RDR2 generations load at `0x140000000` (no `[exe-base]` refusal);
  - the menu shows;
  - the run's `pool`, `band` and `limits` events are recorded, with the app's footprint, and
    the helper's or donors' footprint when PLA-216 is on;
  - no `pool=exhausted`.
- **Phone gates:** Hollow Knight `first-frame+10`; RDR2 to the menu with a shot; the
  Compatibility issue created as `Red Dead Redemption 2 (1174180)` (or the Epic ID).
- **Effort:** 4–10 sessions. The genuine protection under FEX is the unknown.

### S4: Story mode (tier c)

- **Do:**
  - load a Story save, or start a new game, at Low and about 720 rows with 3/4 scale, with
    PLA-216's pool on;
  - tune VRAM and reported RAM per title (P7) and the shader cache (P6);
  - `pp perf` with `--cool`.
- **Acceptance:**
  - 10 minutes of Story-mode play with no jetsam and no crash;
  - median fps of at least 15 after the clamp;
  - footprint margin of at least 300 MB at the end, both in the app and in the phone's
    physical RAM (no background app killed, no jetsam of the donors);
  - an evidence record with the IPA sha256, thermal states and budgets.
- **Phone gates:** Hollow Knight `first-frame+10`; RDR2 `pp perf` route twice, cooled; Linear
  Compatibility status "Playable with issues" at best.
- **Effort:** 8–20 sessions. Memory and the GPU-hang family are the risk.

### S5: Performance and stability (after S4)

- **Do:**
  - try per-title FEX levers (AFP off, selective TSO under decision 0021);
  - work on KosmicKrisp's per-draw CPU and vkd3d's one-time submit, if on the DX12 route;
  - try the low-energy loading mode that Madeira measured [M §128] as a Playport setting;
  - run a 30-minute session.
- **Acceptance:** sustained fps +20 % over S4 at equal thermal start; 30 minutes without a
  crash.
- **Effort:** open-ended; 10+ sessions.

Online (tier d) has no stage.
