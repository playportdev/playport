# Portal 2: software-backed PE32 image mapping

## Verdict and limits

The host-side experiment now materializes the real installed Portal 2 launcher
and engine in a software-separated 32-bit guest address space, at both preferred
and relocated guest addresses. Native backing stays above 4 GiB.

**Portal 2 still does not run. No game instructions executed.** This does not
change Wine's actual image loader or provide FEX/WoW64 execution, import binding,
TLS/process setup, graphics, audio or input. The code is not linked into the app.
No phone app was installed, uninstalled, launched or modified in this step;
there is no device-run IPA SHA256 or gameplay result.

## Real files

The inputs are the same privately retrieved files as
[the original inspection](2026-10-01-portal2-32-bit.md), with unchanged hashes:

| File | SHA256 |
| --- | --- |
| `portal2.exe` | `18b57b16d8cf8de731d91bff236bf84fbfe1e08c67169f582086dec0e100a8c8` |
| `engine.dll` | `49ac3268cf27b7e8c7c5f00dea7a45d8e2fa113c913012f5144ef81db754f6df` |

The mapper reads their PE32 headers/sections, copies raw bytes into guest pages,
zeroes BSS, applies i386 HIGHLOW relocations and sets guest page permissions.
It returns **guest** entry/IAT addresses, never truncated host pointers. The
relocation directory is snapshotted before application, preventing a fixup from
rewriting records that are still being parsed.

With simulated 16 KiB host granules:

| Image | Guest base | Guest entry | Image size | HIGHLOW fixups | Imports inspected |
| --- | --- | --- | --- | --- | --- |
| launcher, preferred | `0x00400000` | `0x004017d1` | `0x0005c000` | 0 | 70 |
| launcher, relocated | `0x20000000` | `0x200017d1` | `0x0005c000` | 919 | 70 |
| engine, preferred | `0x10000000` | `0x1030af6c` | `0x0074b000` | 0 | 444 |
| engine, relocated | `0x20000000` | `0x2030af6c` | `0x0074b000` | 146206 | 444 |

The relocated images were mapped one at a time, not together at the same base.
Entry bytes could be fetched through checked software translation; they were
not called. Import inspection traverses descriptors, named/ordinal lookup
entries and IAT slots, but resolves none of them.

An independent comparison used the installed Python PE parser's
`get_memory_mapped_image`, rebased where needed and zero-padded to SizeOfImage.
Every byte of all four mapped image variants matched its reference output:
376,832 launcher bytes and 7,647,232 engine bytes per variant. This is image
materialization equivalence, not a Windows loader/execution verdict.

## Checks

- `pp test --quick`: passed (479 tooling tests and all host C tests, including
  both guest32 memory and PE32 mapping tests).
- `pe32_test.c`: synthetic images with native, 16 KiB and 64 KiB host granules;
  all 2048 truncated lengths; malformed headers, directories, section extents,
  overlap, import strings/thunks and relocations; conflicting reservations;
  entry permissions; failure rollback; 32-bit edge/relocation arithmetic; and
  4096 deterministic input mutations.
- AddressSanitizer + UndefinedBehaviorSanitizer: passed, including both real
  files at both guest addresses.
- `pe32.c` cross-compiles for `arm64-apple-ios26.5` with
  `-Wall -Wextra -Werror` against the recorded SDK. Not executed on iOS.
- Full-image independent comparisons: passed with zero differing bytes.

Implementation, experimental format/resource limits and repeatable host-test
commands: [build/guest32](../../build/guest32/README.md). Private binaries, game
files, the reference comparison script and logs remain under `.work/guest32/`
and `.work/portal2-files/`. No game data is committed.

## Next execution gate

The old Wine image-map failure is **not fixed in the shipped runtime** by this
experiment. The next bridge must preserve these guest addresses in FEX decode,
every emitted memory access and exceptions, then marshal them at Wine syscall
and callback boundaries. Directly pointing the existing WoW64 module at the
high backing would still pass invalid low pointers to native code. A real
32-bit instruction test remains a prerequisite for claiming execution. The
subsequent [phone-side reservation test](2026-10-02-guest32-device-memory.md)
passes the native memory gate, but does not exercise this PE mapper or FEX.
