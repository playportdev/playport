### Misplaced clean picks (the PLA-393 check)

The written series was replayed as `build/lib.sh apply_series` does (`git am -3` onto
wine-11.20, one patch at a time), and each commit's tree was compared with its rebase pick.
Two "clean" picks, kept as their old files, applied at the wrong offset:

- **wine-port 0033** (`ml487` read checksum): its `done:` hunk in `dlls/ntdll/unix/file.c` landed
  in `NtWriteFile`, not `NtReadFile` (WineHQ removed about 400 lines of cdrom/volume code above).
- **wine-unix 0035** (job-loop I/O completion log): its hunk landed in the wrong
  `NtSetInformationFile` case.

Both were re-exported from their rebase-tree commits (new line numbers and index lines only,
trailers unchanged). After that all 229 wine-pe-stack picks and all 224 wine-unix-stack picks are
tree-equal, and the built `run/pe/wine` (below 0047) and `run/unix/wine` trees equal the rebase
tips. Neither `flags.txt` nor the range-diff could see either misplacement.

## The replacements (madeira-unix 0160, class `madeira-port`)

WineHQ commits in 11.19..11.20 that touch a file a `*_ios.c` replacement overrides, and the
server protocol (which did change):

- **Carried:** `eba8937` into `thread_ios.c` (`set_thread_info` now carries `system_affinity`, and
  a group affinity is `SET_THREAD_INFO_GROUP_AFFINITY`). Needed: the server's `thread.c` is built
  from the wine tree and now masks with `system_affinity`, which a zeroed request leaves 0, so
  every `SetThreadAffinityMask` would have failed. `cf50ea1` into `fd_ios.c` (the
  `unmount_device` request replaces `FSCTL_DISMOUNT_VOLUME`); needed to link, since the handler
  table names `req_unmount_device`. `251a061` (cdrom.c removed): `ntdll-unix/build.sh` no longer
  builds or archives `cdrom.o`, and `cdrom_stub.c` is gone. `1c4cb6c` into `sysparams_ios.c`
  (an EDID without a monitor id still gives its other fields).
- **Not carried:** `7fb24b7` (reserved CPSR bits in `signal_arm64.c` and `thread.c`): a hand port
  of its own (W8b). The 14 `virtual.c` commits (reserved areas, address-space limits, the 8 GiB
  low reserve): the Linux preloader's layout, which `virtual_ios.c` decides for iOS, as with
  11.19's three.
- The build's unix stage compiled every replacement with 0 failures. Its `libwineserver.a`
  link test reports the same four duplicate symbols as before this move (W7's build had them
  too); the `ws4` link is OK.

## Build-system consequences of 11.20

- **The arm64ec programs (decision 0082).** WineHQ `886f2ea` moved the per-architecture choice
  from configure into each module's Makefile.in (`ENABLE_ARCHS`). The first 11.20 build dropped
  `conhost`, `lsass`, `plugplay`, `rpcss`, `services`, `spoolsv`, `termsv`, `winemenubuilder`,
  `wuauserv` (now `$(HOST_ARCH)`) and `winevdm` (`$(WIN16_ARCH)`) from `Runtime/arm64ec-windows`.
  It also added `explorer.exe` and `winedbg.exe`, which 0082 keeps out, because
  `--enable-<program>` no longer chooses architectures. The conservative choice keeps 0082's
  outcome:
  - `patches/wine-pe` 0047 adds `arm64ec` to those ten programs' `ENABLE_ARCHS`;
  - `stages/wine-pe.sh` now passes `--disable-` for `winetest`, `winedbg`, `wineboot` and
    `explorer` in the arm64ec tree.

  With both, the staged arm64ec program set is what it was on 11.19. The only module changes
  are upstream's: `wpnapps.dll` is new in all three sets, and `unicows.dll` is now i386-only
  (`ENABLE_ARCHS = i386`), so it is gone from the aarch64 and arm64ec sets. 0082's sentence
  about the mechanism is now out of date; `docs/BUILDING.md` describes the new one.
- **The prefix registry seed.**
  - **quartz.** WineHQ `15fc319` registers quartz's new Color Space Converter in
    `DllRegisterServer`, so `prefix-registry.py --check` stopped at `MEDIA_REGISTER_SHA256`. The
    process asks for a refresh from a desktop prefix of this Wine; this workstation has no
    desktop wine-11.20. Instead the one new entry was derived (the instance key under
    `CLSID_LegacyAmFilterCategory`, `FriendlyName`, `CLSID` and `FilterData`). `FilterData` comes
    from a Python port of `FM2_WriteFilterData` (`dlls/quartz/filtermapper.c`), which reproduces
    three desktop-prefix entries of `wineboot-media.reg` byte for byte: ACM Wrapper, Video
    Renderer, and the three-pin MPEG-I Stream Splitter. The entry is marked as derived in the
    file's header, and quartz's digest is updated. The coclass registration comes from the
    widl script as before.
  - **VC runtime.** wine.inf's `[VCRuntime.*]` moved to 14.51.36247.00 (Bld `0x8d97`, Minor 51).
    The seed's `VC_RUNTIME` is documented as "as wine.inf writes it at the wine pin", so it and
    its test follow.
  - The seed is regenerated (`pp registry`; `--check` passes): the Color Space Converter's
    CLSID, its filter instance and the VC runtime key.
