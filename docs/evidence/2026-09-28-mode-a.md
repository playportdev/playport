The question (plan [runtime risks](../plans/finished.md#runtime-risks),

this record holds what it rests on.

## Where mode A came from

- Madeira `d032ac9` (2026-04-30), the commit that first ran x86-64 code
  through FEX: "pre-allocates 96MB before the JIT pool to push iOS ASLR past
  the 'mode A' zone (pool < 0x119000000) where the dispatcher branches to
  zero memory". Its `StikJITHelper` comment: a 128 MiB pool at
  `0x114`-`0x117xxxxxx` failed, at `0x119000000` or above it did not, "so
  dispatcher at +0x7ffc130 has top byte 0x12".
- The same day's FEX fork commit `83e12849f` ("mode B", `patches/fex-port`
  0015): seven `stp` of a `SpillStaticRegs` site came out as stale words.
  `db4f32768` (2026-05-11, 0020): the FEX PE's stores to the RX address "are
  silently absorbed ... one specific store per 7-store sequence (often
  pair-5) never landing"; writing through the RW alias "always lands".
- The FEX fork's history (`willfaust/FEX` `ios-port-2607`, fetched for this
  record): until `61f11e3cc` (2026-07-03) `Buffer::WritePtr` added
  `WriteOffset` only under `__APPLE__`, which the Windows-targeted PE build
  never defines, so every emitter store went to the RX address and through
  ntdll's Mach store emulator (Madeira `signal_arm64_ios.c` at `d032ac9`,
  "Emulate stores to JIT-pool RX aliases"). `61f11e3cc` added
  `FEX_IOS_HOST` to that condition with the offset forced to 0 at run time;
  `6084de076` (2026-07-06) turned it on.
- In today's FEX (`Dispatcher.cpp`, `NoBlock`), the dispatcher reaches
  `CompileBlock` only through `ldr x4, l_CompileBlock; blr x4`, with
  `l_CompileBlock` a `dc64` written at the dispatcher's end after the code.
  A zero literal is a branch to zero before any block runs: mode A's
  symptom. A lost `ldr` fixup would leave imm19 = 0 (`LoadStoreLiteral(Op,
  rt, 0)`), which loads the `ldr` itself, not zero. Every `Bind` is
  pc-relative within the 16 KiB dispatcher buffer and uses RX addresses at
  both ends (`Emitter.h`); none depends on the buffer's address.

Why April's lost stores tracked the pool's address is not established; no
build of that era was rebuilt for this record.

below the TEB's, which ntdll creates later: the probe checks the same
mechanism one slot away, and the result's `teb` field gives the TEB's own
slot.

## Not checked on the phone

- `patches/fex` 0007's refusal (FEX without `WINE_IOS_JIT_RW`/`RX`): the
  host sets both before any process starts, and ntdll's own pool setup needs
  them too, so there is no way to reach it on the phone without breaking
  ntdll first. It returns the same `STATUS_UNSUCCESSFUL` as the TEB-slot
  import just above it.
- The pool-side refusals (`pool-*`, `alias`) on the phone: their rules are
  in `app/tests/selfcheck_test.c`; only the host-side refusal was shown.
- The release build (it builds the same Swift; not played).
