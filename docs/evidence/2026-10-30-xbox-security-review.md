# Xbox security review of the whole path

**Date:** 2026-10-30. **Linear:** [PLA-507](https://linear.app/playportdev/issue/PLA-507).
**Kind:** a code review of `dev/pla-485-xbox-store` that read the code only, made before the
review fixes landed (commits up to `7951b3b`). Nothing was run on the phone.
**Scope:**
- **Accounts:** sign-in, the synthetic device, and Keychain use.
- **Runtime:** the bridge and the guest environment.
- **Content:** decryption at rest, package integrity and the CDN.
- **Logs:** logs and redaction.
- **Patches:** `patches/xgameruntime` and `patches/wine-gdk`.
- **Release:** the release gate.

## Constraint

The app, Wine and the game share one process ([0004](../decisions/0004-steam-session-boundary.md)), so
guest code that can load native code reaches the app's Keychain whatever this path does. What
the review weighs is plain Win32 code (any title or mod, from any store): it can write the
shared prefix and `C:\Games`, and it can talk to the bridge.

## Code findings and what was done

|#|Severity|Finding|Fix|
|---|---|---|---|
|A1|High|The CDN serves plain HTTP. The XVD header signature was not checked, so the hash tree's only anchor was attacker-replaceable. A network attacker could swap a plain DLL and run code in the app.|`79d52b3`: before any further fetch, the header is verified against Microsoft's retail keys, which are taken from the GDK's `xsapi.dll` and whose hashes match xvdtool's list. The signed range is 0x200..0x1000, and the pilot's real header verifies. Unsigned, test-signed and encryption-disabled packages are refused. MSIXVC2's signer is not public, so every segment must be encrypted under a licence-wrapped key.|
|A2|Medium|The bridge's client ID, full trust and related products came from `MicrosoftGame.config` in the game folder, which any guest can rewrite.|`4915bac`: these are recorded at install and update from the hash-checked package, and Play refuses when the folder's config differs.|
|A3|Low/Medium|No ticket caching and no rate limit on the bridge.|`a2aa83d`: per-play tickets are cached until 60 s before expiry, and Microsoft calls are limited to 10 per play, plus one every 10 s.|
|A4|Low|Runtime output reached the dev log unscrubbed. The JWK `d` and `KeyBlob` had no pattern.|`9985615`: every pulled `.log` is scrubbed with `pp secrets`' patterns, and both redaction surfaces gained the two patterns.|
|A5|Low|Patch 0002 searched the bridge reply with `strstr` without bounds.|`24dcca1`: the reply is parsed with `xmlReadMemory` within its stated size.|
|A6|Medium|One save-conflict answer overwrote every container, the destructive choice sat on A, and the card survived sign-out.|`24dcca1` and `c1f90b6`: the runtime asks one question per container and makes a recovery copy of the cloud side before any upload. In the app, "decide later" is the default, keeping the phone's copy takes Y twice, and sign-out closes the card.|
|A7|Low|Several weaknesses:<ul><li>XML refused DTDs by searching the text, and UTF-16 got past that.</li><li>Unsigned SOAP replies were accepted, with a non-constant-time HMAC compare.</li><li>Keyed bridge connections never timed out.</li></ul>|`b2010af` and `a2aa83d`: the parser accepts UTF-8 only and refuses DTDs. SOAP replies must be signed, compared in constant time. Idle keyed connections close after 5 minutes.|

## Sound as reviewed

- **Bridge:** binds 127.0.0.1 only. Its 256-bit key comes from the system's secure random generator, is sent first, and is compared in constant time. Frames are capped at 64 KiB, at most 8 connections are allowed, and requests are bound to the playing product. Sign-out revokes it.
- **Guest variables:** they reach the title's environment only. They are never `setenv`'d in the app, and logs name them, never their values.
- **Keychain:** items are this-device-only and never synced. Sign-out deletes everything but `device`, and a reset replaces `device`.
- **Synthetic device:** generated by the system's secure random generator, with no phone identifiers.
- **Sign-in page:** a non-persistent web view that accepts script messages only from the main frame of `https://login.live.com`.
- **In-place swap:** refuses symlinked paths, writes with `O_EXCL|O_NOFOLLOW` and fsyncs before rename. A crash marker lets the next start finish it.
- **CDN socket client:** accepts only `*.xboxlive.com` and follows no redirects. A 206 must match the request exactly, and chunked or encoded bodies are refused.
- **Release:** no Swift Xbox code is reachable in the release app.

## Left for the owner and the phone

- **Residual risks for the release decision**: [PLA-527](https://linear.app/playportdev/issue/PLA-527).
  - Tickets outlive sign-out ([0167](../decisions/0167-xbox-guest-tickets.md)), and guest caches stay in the shared prefix and in backups.
  - Licence signatures are not verified, and the offline lease follows the phone's clock.
  - Requests identify themselves as Xodus Nexus.
  - Plaintext lingers outside the in-place swap.
  - The Keychain outlives the app.
  - The account hash in the guest environment can be reversed.
  - The native runtime DLLs and `wine-gdk` ship in release too, inert without a bridge.
- **Phone measurements** ([PLA-528](https://linear.app/playportdev/issue/PLA-528)):
  - **Not measured yet:** ticket lifetimes in the guest, which 0167 asks for.
  - Prefix caches after play, sign-out and restart.
  - Plaintext after a kill.
  - CDN HTTPS.
  - Device name.
  - Log scans.
  - Bridge rate.
  - Keychain protection classes.
