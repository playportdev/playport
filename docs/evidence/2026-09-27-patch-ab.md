# Patch A/B on Hollow Knight: DXMT as a release build, and the call-return prediction

**Date:** 2026-09-27. **Tree:** origin/main `9d03005` plus one change per IPA,
each built from the one before it. **Phone:** iPhone Air (`iPhone18,4`),
iOS 27.0, over netmuxd Wi-Fi, on battery (`ExternalConnected: false` in every
run's `power.txt`); the battery fell from 65 % to 33 % over the runs below.

**Result:**

- **DXMT's PE side was built at `-O0` with asserts on.**
  `build/stages/dxmt-patched.sh` ran `meson setup` without `--buildtype`, so
  `d3d11.dll`, `dxgi.dll`, `winemetal.dll` and `d3d10core.dll` were meson's
  default debug build. FEX is built at `-O3`, Wine's PE side at `-O2`, and
  DXVK and vkd3d-proton at `--buildtype release`. As a release build, DXMT's
  encode thread does **37 % fewer** instructions a frame in play, Unity's
  graphics worker 13 % fewer, and all threads 7 % fewer.
- **FEX's call-return prediction was off on iOS.** fex-port 0037 (Madeira
  ml305) made every guest RET pop the call-return stack and then take the L1
  lookup, while the push, the pop and the stack resets were still paid.
  `patches/fex` 0006 takes upstream's branch again. The Unity main thread then
  does **7 % fewer** instructions a frame, the graphics worker 8 % fewer and
  all threads 5 % fewer. No run logged `[iOS-bogusrip]` or `CALLRET_OOB`, a
  fault, or a crash report.
- **The frame rate does not show either.** Every run's thermal power budget
  parks the P cores from about 95 s after the first frame, and play then runs
  on the E cores at 73 to 81 FPS whatever the build. The instruction counts do
  not depend on that: they are the measure here.

## 3. Checks

- Each IPA: `pp ui --play app-367520 --until first-frame+10 --shot`, the main
  menu at 118-120 FPS.
- E: a New Game on an empty profile plays the prologue cinematic in the
  right colours at 24.99 FPS (40 ms frames) and reaches King's Pass with the
  Knight in control at 120 FPS. `s1-host.log` has
  `winegstreamer_unix_call_funcs` and no `arm64ec_thread_init` failure,
  `_wassert`, `NtTerminateProcess` or `WindowsVideoMedia error`.
- Every run: no `[rpm-poison]`, `[rpfree-skip]`, `HOST MAP FAILED`,
  `[iOS-bogusrip]` or `CALLRET_OOB`. All runs, A included, log 16
  `[rpm-avail] ml607 CORRUPT op=consume` lines.

A release build of DXMT also compiles out its asserts, which caught the
video path's deptrack bug ([2026-09-26-hk-video.md](2026-09-26-hk-video.md)
§8). A change to DXMT's tracking is worth one run with `-Db_ndebug=false`.
The prediction was measured on Hollow Knight only; ml305's original cases were
Thumper and Steam's CEF.

The run directories are in the main checkout's `$PLAYPORT_BUILD/patch-review/runs/`.
