## Fixes made on the way

- **madeira-unix 0274.** `Wow_loader.dll` copies its image into a pagefile section and maps it twice
  (read-write and read-execute) over its own image range. `mprotect_exec` backed the read-execute view
  with a JIT-pool slot (vm_remap), detaching it from the section, so it held zeros. In an ARM64EC process a
  section's view now keeps the section's memory (read, plus write when asked; the host never runs x86-64
  code). Log: `[anon-view] section view 0x73f8f70000+0x2030000 keeps its section's memory, r-`.
- **wine-pe 0059.** Only an image's view reached FEX's executable intervals, so the read-execute view
  decoded as NOEXEC. An executable view of a plain section is now told to FEX as a protection change
  (`[map-notify] executable view of a plain section … told to FEX`).

## The open blocker: `int3` in Wow_loader on the main thread

- Just before it the client writes 8 bytes at ntdll+0xca5a0, which is `pWow64PrepareForException`
  (`[exec-req] #2 addr=…EAA5A0 size=8 new_prot=40`): it hooks exception dispatch through the pointer the
  x64 `KiUserExceptionDispatcher` reads. It then calls `Wow_loader.dll`+0x125bf0, a fatal routine that
  calls `+0x1e4f200` (prologue, then `int3`); its SEH handler (`+0x20069b4`) starts `BlizzardError.exe`.
- Desktop Wine 11.20 with the same build's `Wow.exe` and `wow_loader.dll` (12.1.5.70688, copied off the
  phone into `.work/wowdesk`) reaches the login screen. Its first breakpoints are at `+0xaa2680` on a
  worker thread, caught by the same handler and unwound; the main thread never reaches `+0x125bf0`.
- Lead, not yet tested: Wine's ARM64EC x64 `KiUserExceptionDispatcher` thunk calls the hook and then
  `ret`s back to the ARM64EC dispatcher, while x64 Windows (and Wine's x86-64 one) go on to
  `RtlDispatchException` in the same x64 code. A client that parses that code to find its continuation
  may fail here. Other candidates: what the client checks of ntdll's x64-visible code, CPUID or timing
  under FEX. Desktop decrypted dump: `.work/wowdesk/runs/desk-dump/loader.bin` (base-relative).
