# Vulkan backend: Hollow Knight on Direct3D 11 (DXVK) and Direct3D 12 (vkd3d-proton)

**Date:** 2026-09-26. **Kind:** device runs (iPhone Air, A19 Pro, iOS 27.0).
**IPA (dev):** sha256 `74b37dfcf0a2b58d41dce68eb5096dcb9fe01cee35cc848a5864b88bcd4a8f1d`.
**Title:** Hollow Knight (app-367520, Unity 6000.0.61), game page set to Vulkan.
Direct3D 12 through the game page's arguments, `-force-d3d12` (its player log
reads `Direct3D: Version: Direct3D 12 [level 11.1]`).

## Result

| API | layer | main menu | gameplay |
| --- | --- | --- | --- |
| Direct3D 11 | DXVK `52fe923` on KosmicKrisp | 120 fps, Metal HUD `Direct`, GPU 6.8 ms | Dirtmouth, walking, 57 fps (earlier IPA of this series) |
| Direct3D 12 | vkd3d-proton `472989a` on KosmicKrisp | 120 fps, `Direct`, GPU 6.4 ms | Dirtmouth bench, 58 fps (earlier IPA of this series) |

Before these changes the Vulkan backend showed a black screen for the whole
launch. Each cause below was found on the phone and fixed in turn; each fix
was checked by the next run.

## Causes and fixes

1. **The layer's pixel size.** `GameSurfaceView` never set its scale, so the
   CAMetalLayer's `contentsScale` stayed 1 and the Vulkan surface reported
   912x420 for a 2736x1260 swap chain: `VK_SUBOPTIMAL_KHR` on the first present
   and a swap chain recreation. The view now takes the screen's native scale
   (`app/Sources/S1Probe/HostIO.swift`); the trace then reads
   `layer=2736x1260 chain=2736x1260`.
2. **DXVK's threads ran out of FEX's address band.** Every thread carries
   FEX state in the 16 GB host band; with a Unity title's threads, DXVK's
   compiler pool and its frame thread, thread init failed
   (`[callret] RESERVE FAILED`, `THREADSTATE ALLOC FAILED`) and `dxvk-frame`
   never started. The Vulkan backend now starts with
   `DXVK_CONFIG=dxvk.numCompilerThreads = 2` (PlayportKit
   `GraphicsBackend.runtimeEnvironment`; a game's own variables win). No
   thread init fails in the runs above. The band's consumption itself is not
   changed: 17 guest reserves of 512 MB were steered into it
   (`[steer] ... armed=va-pressure`), which is the larger user.
3. **Every game draw was dropped** (`patches/mesa` 0008). DXVK on KosmicKrisp
   runs in tiler mode and records each render pass into secondary command
   buffers. The exported `vkGetDeviceProcAddr` answered from the device's
   internal table, which lacks KosmicKrisp's command trampolines, so secondary
   buffers were not recorded for `vkCmdExecuteCommands`. A draw trace showed
   every game draw with an empty render state (`area=0x0 colors=0`) while
   DXVK's own HUD and blit drew. It now answers as `kk_GetDeviceProcAddr`.
4. **vkd3d-proton's first call faulted** (`patches/madeira-unix` 0030). An
   image that `[data-align]` shifts by less than a page got its x18
   trampolines inside its last page, which the `.tls` protection made RW:
   an EXECUTE fault at `d3d12.dll` pool +0x24010.
5. **Device creation faulted in winevulkan** (`patches/wine-unix` 0004). The
   host copy of `VkPhysicalDeviceLayeredApiVulkanPropertiesKHR` left its
   inner `properties.pNext` uninitialised; the host-to-win conversion walked
   it (the faulting address was the text of an earlier FIXME).
6. **Presents composited at 80 fps** (`patches/mesa` 0012). The Metal WSI
   keeps the layer non-opaque on hardware devices; on iOS that forces
   composition (HUD `Composited`, 80 fps on the 120 Hz panel with 6.7 ms of
   GPU). With the layer opaque: `Direct`, 120 fps, image correct.
7. **Suboptimal on a scaled swap chain** (`patches/mesa` 0011). Wine reports
   the window's client size as the surface extent, so a game with a window
   smaller than the screen got a suboptimal result on every present. On iOS
   the layer scales the drawable, so size no longer makes a present
   suboptimal.

Also fixed on the workstation: `build/stages/unix.sh` kept a copied run
tree's `mythic/wine` link to another checkout's Wine, so this checkout's
unix side had been building from that Wine; it now relinks.

## Not shown

- **The Witcher 3 (1.32, Direct3D 11 only) on Vulkan.** It reaches its first
  frame and then presents about twice a minute; DXVK logs
  `Setting display mode: 800x600@120` and `EnterFullscreenMode: Failed to
  change display mode`, and its render thread stays busy. Not investigated
  further.
- **En Garde!** (Unreal Engine, Direct3D 11 and 12). Its shipping executable
  is Steam DRM-wrapped (`steamdrmp.dll`) and exits `0x35` before creating a
  device, and `EnGarde.exe` only starts that executable as a second process.
  This is not a graphics limit.
- The present-wait and swap-chain recreation path: patch 0010's 100 ms grace
  is still in the series, but no run above needed a recreation.
- Longer play, and the release variant.
