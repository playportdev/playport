# Playport 0.5.0: play with touch, aim with gyro, Vulkan for every game

**No controller? Play anyway.** Playport now draws an on-screen gamepad over the
game, aims with your phone's or your controller's gyro, and turns a physical
controller into a keyboard and mouse for games that only listen to those. Under
the hood, **Vulkan is now every game's graphics backend**, OpenGL games run, and a
lot more of them fit in memory.

## Highlights

### 🎮 On-screen controls, for playing without a controller
With no controller connected, a game with the **Gamepad** layout shows Playport's
controls over the game as it starts: a d-pad, face and shoulder buttons, and two
floating sticks. They take touches and leave the rest of the screen alone.

- **A three-finger tap** anywhere opens Playport's in-game menu (Resume, Controls,
  Screenshot, Performance overlay, Quit game) — with no controller, that is how you
  reach it. The first time the controls appear on their own, a toast says so.
- **Per game:** *Game options › Controls* sets the layout (**Off** or **Gamepad**),
  whether the d-pad shows, where the right stick sits (**Off**, **Below A/B/X/Y** or
  **Above A/B/X/Y**) and the controls' opacity. *Settings › Controls* holds the defaults
  every game follows, and haptics.
- A connected controller hides them and its disconnecting brings them back, so
  nothing is ever on screen twice.

### 🕹️ Any controller as a keyboard and mouse
Many games only listen to a keyboard and mouse, or want a different button than the
one your controller has. *Game options › Controls › Controller* (and *Settings ›
Controls › Controller* for every game's default) maps each input of a connected
controller — buttons, stick, triggers, gyro — to **a controller input, a key with
modifiers, a mouse button, mouse movement or wheel, or a Playport action**:

- **As a controller**, **As keyboard & mouse** or **Custom**, switched at the top of
  the page; Y puts a game's map back to the default.
- Defaults for the controller map include look speed for a stick bound to the mouse,
  so a shooter's aim is adjustable rather than all-or-nothing.

### 🎯 Gyro aim
Aim by moving the phone, or a DualSense, DualShock 4 or Switch Pro controller, with
the output as **the mouse or the right stick**, per game:

- *Game options › Controls › Gyro aim* has the source (**Auto**, so your controller's
  gyro when it has one, else the iPhone's), the output, and sensitivity, smoothing
  and a dead zone; a **test area** on the page shows a dot following the aim before
  you launch anything.
- *Settings › Controls › Gyro aim* holds the defaults, and gyro aim can be turned
  on or off from the in-game menu while you play.

### ⚡ Vulkan is every game's backend
Direct3D 9, 10, 11 and 12 now go to **Vulkan, on KosmicKrisp, Mesa's Vulkan driver on
Metal**, by default — the route that took Red Dead Redemption 2 and The Witcher 3
furthest, with DXVK and vkd3d-proton above it. DXMT stays one choice away in
*Settings › Graphics* or on the game's page, for a game that prefers it.

- **Second launches are smoother:** what the backends translate and compile is kept
  on disk (KosmicKrisp's and Zink's shaders, DXMT's), and so is the code FEX has
  translated, so a second launch and a second visit to an area no longer repeat the
  first one's work. *Settings › Storage › Shader cache* shows how much space they
  take and clears them, Metal's caches included.
- **Metal HUD** and the *Performance overlay* row still show the frame rate over a
  running game, now for either backend.

### 🖥️ OpenGL games run
Games with an OpenGL renderer — GoldSrc titles such as **Half-Life** and
**Counter-Strike**, **Neverwinter Nights**, and other Windows OpenGL games — now draw
through Mesa's Zink on KosmicKrisp, at OpenGL 3.3, in 64-bit and 32-bit games alike.

### 🧠 More room for big games
Every Play's memory is planned before it starts, and memory freed by the game is
handed back for reuse instead of being lost:

- **A memory plan per phone and per game:** guest RAM, the video budget and the
  emulator's own pool are sized together from what the phone actually has and what
  the game asks for.
- **The donor pool** keeps a large block of RAM outside Playport's own footprint and
  backs the game with it, so a title can use more than the app alone could hold.
  *Settings › Graphics › Donor memory* turns it **Off** or leaves it on **Auto**.
- **Bigger titles fit:** in our testing Kingdom Come: Deliverance ran 32 minutes at a
  peak footprint of 3.9 GB where it used to reach 7.7 GB. A game that wants more than
  the phone can hold still ends: the pool widens the ceiling, it does not remove it.

### 💾 Steam, better in 32-bit too
- **Playport's own Steam client now serves 32-bit games as well as 64-bit ones**, so
  a 32-bit game gets the same sign-in, ownership check and online tickets a 64-bit
  one does instead of an emulated stand-in. Portal 2, which is 32-bit, reaches chapter
  1 this way.
- **Repair** can fetch an app's shared depot again, so a game that lost Steamworks
  Shared files is repaired rather than reinstalled.
- A game that Steam refuses ownership of is told apart from one Steam cannot check.

## Also new
- **Windows services**, so a game or launcher that starts one (Rockstar's, for
  example) is not left waiting on a service manager that does not answer.
- **Settings scrolls**, so every section fits a landscape phone.
- **The in-game menu has a Controls panel:** it holds the running game's on-screen
  controls, gyro aim and controller map, and every change applies at once; with no
  controller, its rows and the three-finger tap are how you reach it.
- **Faster synchronisation:** Wine's in-process synchronisation now runs in its own
  thread-safe path, on by default, which is what Proton games expect.
- **Newer components:** Wine 11.20 with Valve's latest Proton Wine changes (and Wine
  Mono 11.3 for .NET games), FEX 5285020d with rpmalloc, current DXMT, DXVK,
  vkd3d-proton, Mesa/KosmicKrisp and the Khronos Vulkan loader.

## Games
The [compatibility list](https://playport.dev/compatibility/) carries every game we
and players have tried, with its status. Since 0.4.0:

- **Now working:** Among Us, Monster Train (GOG), Duck Paradox, Soccer Online: Ball
  3D, Spelunky, Super Meat Boy, BioShock (GOG), Assassin's Creed: Director's Cut

  Final Fantasy III.

## Good to know
- **Vulkan is the default now.** If a game looks or behaves worse than on 0.4.0,
  switch it to **DXMT** on its page (*Game options › Graphics › Direct3D*) and tell us
  which game: it is one setting, and it helps us pick the right default per title.
- **Big games keep needing memory,** and a game that wants more than the phone can
  hold still ends. The donor pool widens the ceiling, it does not remove it.
- **No layout editor yet.** The on-screen controls are the Gamepad layout with its
  d-pad, right stick and opacity options; keyboard-and-mouse and point-and-click
  layouts and a movable layout are next.
- **Gyro aim needs a game that takes a stick or a mouse**; it drives the game's own
  input, so a game with its own separate aim settings still behaves as that game does.
- **Tested on one phone** (iOS 27.0.1). If a game misbehaves, *Report a problem* on
  its page shares one zip with its logs.
- Your games, saves and logins are untouched by this update; install over 0.4.0.

## Install

Download `Playport-0.5.0.ipa` and sideload it with your own Apple ID, keeping the
increased memory limit and the JIT helper extension. If you have an earlier version,
install over it. Bring your own games from Steam, GOG, Epic Games or Files.

The complete Corresponding Source of this exact build, the notices and the
rebuild instructions are attached as `Playport-0.5.0-source.tar`, `NOTICES.tar`
and `INSTALL-REBUILD.tar`. `SHA256SUMS` covers every file.

Playport is GPL-3.0-or-later; every component keeps its own licence.
