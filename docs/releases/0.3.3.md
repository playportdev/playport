# Playport 0.3.3: JIT your way

**Playport now works with the JIT tools you already use.** Its built-in JIT helper
is still the easiest way to play. But if you already enable JIT with
**StikDebug**, or run your apps inside **LiveContainer**, Playport now takes JIT
from them too. You no longer need Playport's own pairing.

## Highlights

### 🔌 Choose where JIT comes from
A new **JIT method** setting in **Settings › Setup check** (or press **X** on the
setup checklist's first step) offers three ways:

| Method | What happens when you press Play |
| --- | --- |
| **Built-in** (default) | Playport's own helper enables JIT, as before. No other app, no app switch. |
| **StikDebug** | Playport opens StikDebug, which enables JIT and brings you back to the game. |
| **Another app** | Playport waits for JIT from the app you use, such as LiveContainer's *Launch with JIT*. |

StikDebug and other apps use StikDebug's standard **`universal.js`** script.
Playport's JIT already speaks its protocol, so there is no custom script to install.

### 📦 LiveContainer support
LiveContainer can't start Playport's built-in helper, so Playport now notices
when it runs inside LiveContainer and hides the Built-in method. Two ways to play:

1. **Launch with JIT** (recommended): in LiveContainer, set the JIT enabler to
   StikDebug with `universal.js`, and turn on *Launch with JIT* for Playport.
   Playport finds JIT already there, so Play doesn't wait for it.
2. **StikDebug from Playport**: choose StikDebug as the JIT method and turn on
   *Use LiveContainer's Bundle ID* in LiveContainer's settings.

### 🧭 A setup that fits your method
- With StikDebug or another app, Playport's own **pairing is no longer a setup
  step**, and a missing pairing never stops a game.
- LocalDevVPN is skipped too when another app brings JIT. StikDebug still uses it.
- While a game waits for JIT, the launch screen says what it is waiting for. If JIT
  doesn't arrive, it tells you what to check for the method you chose.

## Good to know
- **One game per launch.** After a game, Playport normally restarts itself so the
  next one gets fresh JIT. That restart needs Playport's pairing, and inside
  LiveContainer it isn't possible at all. In those cases Playport asks you to close
  it and launch it again (with JIT) before the next game.
- **Built-in is unchanged** and still the default. If it works for you, there is
  nothing to do.
- **Not tested with StikDebug or LiveContainer yet.** Playport is tested on one
  phone (iOS 27.0), which has neither. Built-in was checked with Hollow Knight. If
  you play through StikDebug or LiveContainer, please tell us how it goes.

Thanks to the player who asked for this: *"in app JIT enabling is cool and all,
but it doesn't work under LiveContainer"*. Now it should: let us know.

Everything else is as in 0.3.2.

## Install

Download `Playport-0.3.3.ipa` and sideload it with your own Apple ID, keeping the
increased memory limit and the JIT helper extension. If you have an earlier version,
install over it: your games, saves and Steam login stay. Bring your own games from
Steam.

The complete Corresponding Source of this exact build, the notices and the
rebuild instructions are attached as `Playport-0.3.3-source.tar`, `NOTICES.tar`
and `INSTALL-REBUILD.tar`. `SHA256SUMS` covers every file.
