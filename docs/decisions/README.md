# Decisions

Short records of decisions that shape Playport. Each states the decision, why
it was taken, and what it costs. A decision changes only by a new record that
supersedes it.

| Record | Decision |
| --- | --- |
| [0001](0001-superproject-on-madeira.md) | Build on Madeira as a superproject: a pinned submodule plus patch series, not a fork |
| [0002](0002-linux-only-build.md) | Build, sign and verify on one Linux workstation, with no Mac in the loop |
| [0003](0003-runtime-backend.md) | Run guests with Madeira's stack: Wine ARM64EC, FEX and DXMT in one process |
| [0004](0004-steam-session-boundary.md) | Keep the host Steam session and any guest Steam session apart; no host secret enters the guest |
| [0005](0005-title-cohort.md) | Choose test titles by a scorecard; x86-64 Direct3D 11 only |
| [0006](0006-licence.md) | GPL-3.0-or-later, with the Madeira Converter Exception adopted for Playport's own code |
| [0007](0007-dxmt-on-upstream.md) | Build DXMT from 3Shain/dxmt with Madeira's port rebased as a patch series; FEX next, Wine only on a separate go-ahead |
| [0008](0008-fex-on-upstream.md) | Build FEX from FEX-Emu releases with Madeira's FEX and rpmalloc ports rebased as patch series |
| [0009](0009-dev-and-release-builds.md) | Build a dev app (the harness, the default) and a release app (what a player gets: no harness, a quiet runtime, one size-limited log) from the same trees |
| [0010](0010-jit-without-a-host.md) | A Home Screen launch gets JIT from the app's own helper extension; no host at launch |
| [0011](0011-no-workstation-jit.md) | No workstation provides JIT: driven launches use the built-in helper too |
| [0012](0012-the-ui-is-the-only-entry-point.md) | The UI is the only entry point: the app is self-contained, and the workstation tests it by driving its UI; the probes, side launch modes and staging tools are retired |
| [0013](0013-wine-on-upstream.md) | Build Wine from WineHQ releases with Madeira's fork rebased as a patch series and its replacements ported in `patches/madeira-unix` |
| [0014](0014-vulkan-through-kosmickrisp.md) | Build KosmicKrisp (Mesa's Vulkan on Metal) for iOS from a pin plus `patches/mesa`, with DXVK and vkd3d-proton on it; accepted and shipped by 0015 |
| [0015](0015-vulkan-backend-accepted.md) | Every IPA carries the Vulkan backend (KosmicKrisp, Wine's Vulkan, DXVK, vkd3d-proton), opt-in per game or globally; DXMT stays the default except for detected DX12 games (0044); its compiler-thread limit is dropped by 0024 |
| [0017](0017-encrypted-app-ticket.md) | **Proposed, not accepted:** a game's encrypted app ticket may enter the guest, per game, through one file removed at exit; the one exception to 0004 |
| [0016](0016-agents-share-the-phone.md) | Agents work in parallel, each in its own worktree, and share the phone: one lock and install record, sessions, drivers that refuse another checkout's IPA, driven settings undone after their session; its per-agent checkouts are dropped by 0028 |
| [0018](0018-valve-wine-as-a-series.md) | Keep WineHQ's latest release as the Wine base and carry the Valve (Proton) Wine commits Playport wants as `patches/wine-valve`; Valve's `proton_11.0` branch is not the base |
| [0019](0019-jit-pool-sized-from-the-limit.md) | Size a Play's JIT pool from the memory limit (an eighth, 512 to 896 MiB), end a launch that ran it out as its own outcome, and keep a private ntdll copy per pseudo-process; its sizing is replaced by 0036 |
| [0020](0020-steam-game-id.md) | A Steam game launches with its app ID as Steam's game id (`SteamAppId`, `SteamGameId`, `STEAM_COMPAT_APP_ID`), as Steam sets it and Proton passes it to Wine, so Valve's per-game fixes in `patches/wine-valve` apply; the player's variables for the game win |
| [0021](0021-fex-ordering-per-game.md) | Run FEX with Proton's memory ordering (scalar TSO with half barriers) as each game's default, from Proton's FEX profiles as data, with a per-game override on the game's page; pass FEAT_LRCPC2 from the host to FEX |
| [0022](0022-stop-a-game-that-ran-the-pool-out.md) | Stop a game still running 10 s after it ran the JIT pool out inside the app, by ending its socket to the wineserver; the app stays open on the result screen; since 0030 the restart after the game ends it |
| [0023](0023-in-process-sync-stays-off.md) | In-process NT sync (madsync) stays off: waits keep going to the wineserver, whose round trips measured under 1 % of Hollow Knight's main thread and do not limit The Witcher 3's GPU-bound frame |
| [0024](0024-dxvk-picks-its-compiler-threads.md) | The Vulkan backend lets DXVK pick its compiler thread count (0015's limit of two is dropped): with rpmalloc's 3.7 GB leak fixed and call-return stacks packed at the top, each emulator thread takes 50 MB of FEX's 16 GB host band, which every play now measures (`band:`) |
| [0025](0025-no-git-hooks.md) | The repository carries no git hooks: the licence-adoption and name-gate checks run in `pp test` and CI, not in a pre-push hook (supersedes 0006's hook line) |
| [0026](0026-a-dev-test-title-for-the-jit-pool.md) | The dev build carries one test title, *PoolStress*, a program that starts N child processes to stress the JIT pool, copied into `C:\Games` by the app and played through the UI; an exception to 0012, and the release build carries none of it (superseded by 0035) |
| [0027](0027-titles-as-children-of-a-session-root.md) | One app run plays several games: the first Play starts a session root (`playport-session.exe`, the process's one Wine main) that starts every title as its child in a job; a Play is refused only when the JIT pool is too full; each pseudo-process's emulator gets its own JIT aliases (madeira-unix 0044); narrowed by 0029 and 0030 to one title per process |
| [0028](0028-one-checkout.md) | One checkout: agents work on branches in it, with no per-agent copies (`pp worktree` removed); the build area holds the machine's inputs and the phone's lock; `pp sync` builds its candidate in a throwaway shared clone (changes 0016) |
| [0029](0029-restart-after-each-game.md) | Playport restarts itself after each game that used the runtime (CoreDevice `launchapplication` with `terminateExisting`, sent by the app over LocalDevVPN; idevice built into the app); the session root flushes the registry first; the result screen is replaced by alerts |
| [0030](0030-one-title-per-process.md) | One title per app process: the session root starts one title in a job and idles; the second-title paths (`pool=room`, `JitPool.hasRoomForNextTitle`, the per-case `spent`) and the in-app stop of a game that ran the pool out are removed, and the restart ends such a game |
| [0031](0031-a-mac-for-analysis-only.md) | **Proposed, not accepted:** a borrowed Mac may analyse the installed app with Apple's tools (Instruments, Xcode's Metal debugger, `gpucapture`, `gpudebug`, `metalperftrace`); it never builds, installs or launches ([GPU-DEBUGGING.md](../GPU-DEBUGGING.md#on-a-mac)) |
| [0032](0032-vkd3d-proton-as-a-series.md) | vkd3d-proton carries `patches/vkd3d-proton` (0015 said unmodified): on KosmicKrisp, Direct3D 12 reports feature level 12_0 without sparse binding and shader model 6.6, and places resources wherever the Vulkan memory allows, so Unreal Engine 5's Direct3D 12 renderer runs |
| [0033](0033-on-device-pairing.md) | Generate RP pairing credentials inside Playport on iOS 27 through bounded Bonjour advertising and explicit system trust; store directly in Keychain, with same-phone setup instead of a computer/file guide |
| [0034](0034-a-gamepad-first-ui.md) | A gamepad-first, landscape UI: Home, Library and Downloads on LB/RB, Settings behind ≡, one focus ring and a footer of buttons; the app reads the controller itself (PadRouter) until a game starts; environment variables gone, memory ordering and the Steam API choice dev-only, no compatibility labels (0012 holds) |
| [0035](0035-no-dev-test-title.md) | The dev build carries no test title: *PoolStress* and its build step, copy and checks are removed (supersedes 0026) |
| [0036](0036-one-512-mib-jit-pool.md) | Every Play gets a 512 MiB JIT pool, whatever the memory limit (replaces 0019's sizing): Kingdom Come: Deliverance needs the other 384 MiB for its Rattay load, and no game measured needs more pool |
| [0037](0037-ipas-on-github-releases.md) | Official IPAs are free downloads on GitHub Releases, uploaded by hand with their exact source, notices and checksums, never by CI; donations go through Ko-fi or Patreon and buy no software or rights; replaces the itch.io plan in RELEASE-HOSTING.md |
| [0038](0038-unsigned-release-ipas.md) | A release's IPA is the release variant signed ad hoc with its entitlements and no team, profile or device (`pp build --unsigned`), for the recipient to re-sign; `pp release VERSION` builds it clean on the workstation, runs the gates and makes a GitHub draft pre-release, never published by the tool; the version is `CFBundleShortVersionString` (0.1.0 first) |
| [0039](0039-owners-licensing-review.md) | The owner settles the open licensing questions: LLVM exception accepted, FreeType under FTL, metadata-written notices for three crates without licence files, best-effort notices for StikJIT and GStreamer, Madeira read as GPL-3.0; Apple SDK risk accepted; history rewritten at publication (replaced by 0043); no donation page for 0.1.0 |
| [0040](0040-patch-series-under-upstream-licences.md) | Playport's lines in `patches/vkd3d-proton`, `patches/gbe` and `patches/idevice` are offered under each upstream's licence (LGPL-2.1-or-later, LGPL-3.0, MIT), as the Wine and Mesa series are |
| [0041](0041-codecs-supersets-and-relinking.md) | No request to Madeira's author; the owner accepts FFmpeg's H.264/AAC/MPEG codec patent risk; the whole-superset notices close the linked-member audits (OpenLDAP 2.8 taken as GPL-compatible); rebuilding from the Corresponding Source is the relinking route, with no per-component relink test |
| [0042](0042-the-source-bundle-is-complete.md) | The source bundle is complete: GStreamer's permissive parts (MoltenVK, Rust) and StikJIT's MIT idevice owe notices, not source; the recipient builds from the public repository at the release tag, whose sources the bundle holds; the archive-fed component trials are removed |
| [0044](0044-vulkan-default-for-dx12.md) | Detected DX12 launches default to Vulkan, from executable imports or launch flags; explicit graphics choices still win, and other games stay on DXMT |
| [0045](0045-library-store-copies.md) | Library defaults to All, then Installed and store filters; small source badges distinguish separate store copies, joined only by store identity |
| [0046](0046-static-direct3d-evidence.md) | Best-effort Direct3D 8–12 evidence from selected EXE API/library imports, reachable local DLLs and guarded dynamic-loading references; unknown is not DX11, explicit choices still win |
| [0047](0047-i386-titles-on-vulkan.md) | i386 Direct3D 9 titles join the cohort (extends 0005) as WoW64 children through the Portal 2 plan's guest window; an i386 executable defaults to Vulkan (DXVK d3d9 on KosmicKrisp), x86-64 titles keep 0044's rule; explicit choices still win |
| [0043](0043-published-as-the-playport-authors.md) | Published as "The Playport authors" <dev@playport.dev>, bundle ID `dev.playport.app`, from one squashed commit in a new repository (playportdev/playport, site playport.dev); the history rewrite is retired; `pp secrets` checks the build area's `private-words`; source first, then 0.1.0 |
| [0048](0048-x87-reduced-precision-global.md) | FEX runs x87 at 64-bit precision for every game, Proton's global `X87ReducedPrecision=1` (supersedes that part of 0021); Proton's per-game entries still go over it, and a dev build's game page has a Default/64-bit/80-bit picker; Proton's other global values unchanged |
| [0050](0050-release-reuses-the-build.md) | `pp release` reuses the newest unsigned release build of HEAD, or builds it incrementally; `--clean` builds every tree afresh (changes 0038, which always built clean) |
| [0051](0051-jit-from-another-app.md) | Settings › Setup check offers three JIT methods in both variants: Built-in (default), StikDebug (`stikdebug://enable-jit` with `universal.js`) and Another app (wait for LiveContainer's Launch with JIT, SideStore…); Built-in is hidden inside LiveContainer, and without the pairing or inside LiveContainer Playport asks to be closed and relaunched after a game instead of restarting itself (narrows 0009, 0010, 0011) |
