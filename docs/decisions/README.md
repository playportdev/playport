# Decisions

Short records of decisions that shape Playport. Each states the decision, why
it was taken, and what it costs. A decision changes only by a new record that
supersedes it.

| Record | Decision |
| --- | --- |
| [0001](0001-superproject-on-madeira.md) | Build on Madeira as a superproject: a pinned submodule plus patch series, not a fork |
| [0002](0002-linux-only-build.md) | Build, sign and verify on one Linux workstation, with no Mac in the loop |
| [0003](0003-runtime-backend.md) | Run guests with Madeira's stack: Wine ARM64EC, FEX and DXMT in one process |
| [0004](0004-steam-session-boundary.md) | Keep the host Steam session and any guest Steam session apart; no host secret enters the guest |
| [0005](0005-title-cohort.md) | Choose test titles by a scorecard; x86-64 Direct3D 11 only |
| [0006](0006-licence.md) | GPL-3.0-or-later, with the Madeira Converter Exception adopted for Playport's own code |
| [0007](0007-dxmt-on-upstream.md) | Build DXMT from 3Shain/dxmt with Madeira's port rebased as a patch series; FEX next, Wine only on a separate go-ahead |
| [0008](0008-fex-on-upstream.md) | Build FEX from FEX-Emu releases with Madeira's FEX and rpmalloc ports rebased as patch series; its pin source is superseded by 0049 (FEX `main`) |

| [0011](0011-no-workstation-jit.md) | No workstation provides JIT: driven launches use the built-in helper too |

| [0018](0018-valve-wine-as-a-series.md) | Keep WineHQ's latest release as the Wine base and carry the Valve (Proton) Wine commits Playport wants as `patches/wine-valve`; Valve's `proton_11.0` branch is not the base; picks come from bleeding-edge since 0049 |
| [0019](0019-jit-pool-sized-from-the-limit.md) | Size a Play's JIT pool from the memory limit (an eighth, 512 to 896 MiB), end a launch that ran it out as its own outcome, and keep a private ntdll copy per pseudo-process; its sizing is replaced by 0036 |
| [0020](0020-steam-game-id.md) | A Steam game launches with its app ID as Steam's game id (`SteamAppId`, `SteamGameId`, `STEAM_COMPAT_APP_ID`), as Steam sets it and Proton passes it to Wine, so Valve's per-game fixes in `patches/wine-valve` apply; the player's variables for the game win |
| [0021](0021-fex-ordering-per-game.md) | Run FEX with Proton's memory ordering (scalar TSO with half barriers) as each game's default, from Proton's FEX profiles as data, with a per-game override on the game's page; pass FEAT_LRCPC2 from the host to FEX |
| [0022](0022-stop-a-game-that-ran-the-pool-out.md) | Stop a game still running 10 s after it ran the JIT pool out inside the app, by ending its socket to the wineserver; the app stays open on the result screen; since 0030 the restart after the game ends it; 0112 gives the Rockstar launcher's Open 240 s |
| [0023](0023-in-process-sync-stays-off.md) | In-process NT sync (madsync) stays off: waits keep going to the wineserver, whose round trips measured under 1 % of Hollow Knight's main thread and do not limit The Witcher 3's GPU-bound frame; superseded by 0052 for fastsync (madsync stays off); 0054 ports fastsync as a Playport patch, on by default |
| [0024](0024-dxvk-picks-its-compiler-threads.md) | The Vulkan backend lets DXVK pick its compiler thread count (0015's limit of two is dropped): with rpmalloc's 3.7 GB leak fixed and call-return stacks packed at the top, each emulator thread takes 50 MB of FEX's 16 GB host band, which every play now measures (`band:`); its empty `DXVK_CONFIG` is replaced by 0066 |
| [0025](0025-no-git-hooks.md) | The repository carries no git hooks: the licence-adoption and name-gate checks run in `pp test` and CI, not in a pre-push hook (supersedes 0006's hook line) |
| [0026](0026-a-dev-test-title-for-the-jit-pool.md) | The dev build carries one test title, *PoolStress*, a program that starts N child processes to stress the JIT pool, copied into `C:\Games` by the app and played through the UI; an exception to 0012, and the release build carries none of it (superseded by 0035) |
| [0027](0027-titles-as-children-of-a-session-root.md) | One app run plays several games: the first Play starts a session root (`playport-session.exe`, the process's one Wine main) that starts every title as its child in a job; a Play is refused only when the JIT pool is too full; each pseudo-process's emulator gets its own JIT aliases (madeira-unix 0044); narrowed by 0029 and 0030 to one title per process |
| [0028](0028-one-checkout.md) | One checkout for builds (`pp worktree` removed), with the machine's inputs and phone lock; 0069 permits owner-authorized isolated host-only worktrees and corrects its build-lock waiting claim; 0054 makes default `pp sync` watch-only (changes 0016) |
| [0029](0029-restart-after-each-game.md) | Playport restarts itself after each game that used the runtime (CoreDevice `launchapplication` with `terminateExisting`, sent by the app over LocalDevVPN; idevice built into the app); the session root flushes the registry first; the result screen is replaced by alerts |
| [0030](0030-one-title-per-process.md) | One title per app process: the session root starts one title in a job and idles; the second-title paths (`pool=room`, `JitPool.hasRoomForNextTitle`, the per-case `spent`) and the in-app stop of a game that ran the pool out are removed, and the restart ends such a game |
| [0031](0031-a-mac-for-analysis-only.md) | **Proposed, not accepted:** a borrowed Mac may analyse the installed app with Apple's tools (Instruments, Xcode's Metal debugger, `gpucapture`, `gpudebug`, `metalperftrace`); it never builds, installs or launches ([GPU-DEBUGGING.md](../GPU-DEBUGGING.md#on-a-mac)) |
| [0032](0032-vkd3d-proton-as-a-series.md) | vkd3d-proton carries `patches/vkd3d-proton` (0015 said unmodified): on KosmicKrisp, Direct3D 12 reports feature level 12_0 without sparse binding and shader model 6.6, and places resources wherever the Vulkan memory allows, so Unreal Engine 5's Direct3D 12 renderer runs |
